## Result

**The merge stage cannot repair the duplicates that the association stage creates. This is by
construction, not by tuning.** Both stages use the same attribute-similarity function
(`lost_similarity_detailed`, `/DATA/GRAPH-API/lost3dsg/src/perception_module/nlp_utils.py:340`).
The description term carries 50 % of the weight. Two VLM descriptions of one object seen from two
views have a sentence-embedding cosine of 0.36–0.83 (exact, n = 21, see below). The merge gate
(0.925) needs that cosine to be at least 0.850 even when label, colour and material all agree.
Zero of the 21 measured pairs reach it. The gate has no geometric term at all: a pair with
identical fused boxes (IoU 1.000, 0.00 m apart, same label, same colour word, same material word)
was refused on similarity 0.889.

The association gate (0.85) needs the same cosine to be at least 0.700. The median measured value
is 0.685. So a re-observation of a known object is refused by association (new object created),
and the merge, which is required to be strictly stricter (GA-341), can never take it back.
This is why the GA-493 run applied 119 additions and 20 updates for 139 observations, and why 84
of 104 final objects have exactly one view.

### The description term, solved exactly

Weights (`config.yaml`, `similarity:`): label 0.05, colour 0.30, material 0.15, description 0.50.
For a pair whose label, colour word and material word are identical strings, the code returns 1.0
for those three terms without consulting any model (string short-circuit in `semantic_similarity`
and `color_similarity_rgb`). The recorded score then gives the description cosine D exactly:
`D = (score − 0.50) / 0.50`. For pairs with material `unknown` on both sides the term is dropped
and `D = (0.85·score − 0.35) / 0.50`.

Over the 21 same-label overlapping pairs refused on similarity that satisfy this condition:
**D min 0.364, median 0.685, max 0.827. The merge gate needs D ≥ 0.850. Zero reach it.**
The identical-box `cabinet#2` pair had D = 0.778.

Ceiling: with everything else perfect, `score = 0.50 + 0.50·D`. At the best measured D (0.827) the
score is 0.914, below the merge gate. The 15 merges that did apply are pairs whose description
strings were identical or nearly so (`rug`/`rug` scored 1.000 three times).

I could not recompute the scores with the real model on this host (`webcolors` and
`sentence_transformers` are absent; the test stub replaces both and returns no embedding). The
derivation above uses only the recorded scores and string equality, so it does not depend on
the model. Rule 2: the stub's "repro" column in my first script was discarded for that reason.

## Defects fixed (worktree commit `f02de48`)

1. **`merged_count` reported decided pairs, not applied merges.**
   `/DATA/GRAPH-API/lost3dsg/src/perception_module/object_services.py`, `_cb_merge_objects`,
   apply block under `with wm.lock:`. A pair whose keeper left the map between the unlocked sweep
   and the locked write was skipped and still counted. A pair whose **discard** left the map was
   not even counted as stale: it fell through to the room-graph update and was reported as a
   merge. The caller (`object_manager_6.py`, `_scan_merge`) logs this number as "merge(s) applied"
   and the GA-493 replay capture records it. Now both cases count as stale and `merged_count` is
   the applied count. A dry run keeps the decided count, because it applies nothing and its
   decisions are its output.
   Check: the GA-393 smoke check now asserts `merged_count == 1` on a clean merge and `== 0` when
   the discard is removed during the sweep. Negative control: on the pre-fix bytes the new
   assertion fails with `a stale pair was counted as a merge: 1`.
2. **`[MERGE AABB] examined=` was multiplied by the hit count.** `_merge_candidates`, legacy
   branch, added `DetectionIndex.last_examined` (a per-query value) once per hit. Diagnostic
   only; no decision reads it.
3. **Two stale tests.** `/DATA/GRAPH-API/lost3dsg/test/test_free_om6.py:137,144` and

## Not changed — the owner's decisions

None of the following is a bug in the code as written. Each is a design choice that the
measurements above show is where the map quality is lost. Changing any of them changes every
decision the system makes, so they need the owner's word.

| Option | What it does | Cost |
|---|---|---|
| A. Switch `association.merge_engine` to `evidence` | Uses the already-written engine in `association.py`: overlap, separation, co-visibility, ontology, room channels fused as log-odds. It has **no description or colour term**, so the ceiling above does not apply. The `channel_overlap` docstring cites a corpus replay over 17 evidence-engine bundles. | Needs `merge_min_consecutive` = 2 sweeps while the pair stays in view (the perception report measured that pairs leave view first). Changes every merge decision. No run since GA-296 gave objects a centroid. |
| B. Add a geometric acceptance to the legacy gate | Accept a same-base-label pair whose measured (or fused) IoU exceeds a threshold, regardless of the description score. Smallest code change. | Introduces a new constant that must be measured, not chosen. Does not touch the association gate, so duplicates are still born and cleaned later. |
| C. Lower the description weight, or cap D | Removes the ceiling in both stages. | Also loosens association; a red book and a blue book at one spot would merge on label alone (the GA-21 case) unless colour is weighted up. |
| D. Room gate reads box overlap | Refuse on room only when the two boxes do not overlap. | Small. Affects 7 pairs in this bundle. |
| E. Distance gate scales with extent, or uses box gap | Lets two halves of a rug or a sofa meet. | Affects 46 same-label pairs here; needs a measured constant. |

My recommendation is A, because it is the only option that already exists in the tree, already
excludes the term that the evidence shows is the ceiling, and already has a corpus replay behind
it. B is the cheapest experiment if A is too broad for the next run.

## Latent finding, not fired in this run (rule 14)

`SemanticEmbedder.__init__` and `.encode` in `nlp_utils.py` swallow every exception. If the
sentence-transformer fails to load in the container, every non-identical string scores 0.0 and
every description embedding is `None`; the description term is then dropped and a same-label,
same-colour pair scores 1.0 (the GA-101 shape). The recorded scores in this bundle are
non-trivial, so the real model answered here. The handler remains.
